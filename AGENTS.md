# REBGE — правила работы агента

Уточнение цели пользователя: получить редактируемый и компилируемый source code,
максимально близко воспроизводящий оригинальную игру. Точность систем и поведения
важнее визуальной полировки и переработки под современные паттерны. Bevy — текущая
среда исполнения и проверки; перенос на другой движок возможен отдельным шагом
после восстановления. Не объявлять реконструированный код исходниками разработчика.

Цель: проверяемая реконструкция Beyond Good & Evil 20th Anniversary Edition
(Jade) на Rust/Bevy с оригинальными ассетами, редактируемыми форматами и
воспроизведением всех систем и game feel. Это собственная реконструкция;
утраченный исходный код разработчика не считается восстановленным.

## Начало и продолжение

Прочитайте `docs/STAGES.md` и `docs/REVERSE_INDEX.md`. Для конкретной ветки
используйте связанные документы; `docs/MODLOG.md` содержит историю доказательств.
При расхождении старых записей актуальная контрольная точка и новые сырые отчёты имеют
приоритет. Стадия4 одобрена, подстадия4.3 завершена в принятом срезе.
Сейчас фиксируется структура/поставка текущей версии перед4.4.

Внутри одобренной стадии выполняйте обычную работу самостоятельно до реальной
необходимости игры или вмешательства пользователя. Новую крупную стадию
согласуйте. Пользователь управляет оригиналом вручную; меню открывается само.
Сообщайте, когда нужна загруженная сцена, задавайте короткий конкретный паттерн
действий и начинайте запись после «готово». Не повторяйте тот же тест без
изменённой гипотезы или метода наблюдения.

## Доказательства и реализация

Повторяющиеся флоу — локальные навыки в `.agents/skills/`: запуск и проверка
игры — `rebge-game-check`; замеры и квалификация записей оригинала —
`rebge-native-measure`; функции и константы Ghidra — `rebge-native-code`;
перенос и проверка Rust/Bevy — `rebge-port-validate`.
Полный цикл native-code audit→гипотеза→case→замер→исправление→регрессия — `rebge-movement-loop`.
Новые узкие субзадачи делегируйте с пустым контекстом и явными goal/files/tools/
acceptance. Игровой ввод обоих targets эксклюзивно у одного агента; остальные
анализируют записи/код. После игрового ввода освободите контроллер и верните
фокус в Codex/ChatGPT. Не делегируйте каждое небольшое действие.
Перед блоком экспериментов оригинала сообщайте сценарии и требуемую площадку,
ждите подготовки пользователем и «готово»; используйте его готовность только
для объявленного блока, пока наблюдения подтверждают подходящую сцену.
Читайте соответствующий `SKILL.md`, когда выполняете этот флоу.

Используйте universal-modder:reverse-engineering; game-automation — для
необходимого наблюдения игры. Ghidra MCP доступен через локальный HTTP и
`tools/ghidra/Read-Ghidra.ps1`; механизмы и ограничения — в `docs/REVERSE_INDEX.md`.
Сохраняйте сырые данные, происхождение, выбранные входы, ошибки и ограничения.
Различайте декомпиляцию, численный результат, последовательное чтение памяти
и проверенное поведение игры. Совпадение части каналов не доказывает целую позу.

Переносите подтверждённые алгоритмы с native f32 порядком операций. Runtime
flags, source flags, root/reference контекст и procedural writers различны.
Недостающие входы остаются явными; приблизительные решения маркируются.
Тесты должны сравнивать независимые native записи, а не повторять реализацию.
Проверка приватных Rust fixtures: `cargo test --offline --manifest-path
bevy/Cargo.toml -- --include-ignored`.

## Структура текущего checkpoint

Runtime API/state — bevy/src/world/animation.rs; data/controller/pose/stepping/
ecs/telemetry — bevy/src/world/animation/. Математические recovered primitives
остаются bevy/src/animation/; input algorithms — bevy/src/input/.
Тесты — bevy/tests/unit/<system>/<feature>.rs, приватные child modules через
cfg(test)/path; новые тесты храните там же. Native fixtures остаются локальными
в reports/, полная library — assets/, detachable runtime pack — asset-packs/.
Используйте --assets или REBGE_ASSETS в launchers для подключения пакета.
Пакет создаётся tools/assets/export_runtime_pack.py; README описывает запуск.
В репозиторий: код/lockfile/tools/docs/AGENTS/.agents/skills. Локальные данные,
бинарные зависимости и сборки исключены .gitignore. Не создавать/публиковать
репозиторий за пользователя. Документы обновлять после milestone/по запросу.
